# Платформа обучения и оценки персонала ПМУ «Эввива» — прототип

Кликабельный прототип платформы для онбординга, обучения и оценки компетенций руководителей и кандидатов на ключевые должности. Сейчас в нём один модуль: **«Юридический блок»**. Он соответствует протоколу № 4 из комплекта документов по оценке.

> Это прототип. Все данные демонстрационные (люди, баллы, решения). Сервера нет: данные хранятся только в браузере (localStorage).

## Как запустить

Откройте `index.html` в браузере. Больше ничего не нужно: нет зависимостей, сборки и сервера.

## Публикация через GitHub Pages

1. Создайте репозиторий на GitHub. Лучше приватный: материалы внутренние.
2. Загрузите содержимое этой папки в корень репозитория (см. ниже).
3. Откройте **Settings → Pages → Build and deployment**, выберите **Deploy from a branch**, ветку `main` и папку `/ (root)` и нажмите **Save**.
4. Через 1–2 минуты прототип будет доступен по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Учтите ограничения GitHub:
- на бесплатном тарифе Pages работает только для **публичных** репозиториев;
- на тарифах Pro и Team Pages можно включить и для приватного репозитория, но сам сайт всё равно будет открыт всем, у кого есть ссылка;
- сайт с доступом только для сотрудников возможен лишь на GitHub Enterprise Cloud.

Если прототип не должен быть публичным, храните его в приватном репозитории без Pages и открывайте `index.html` локально.

### Загрузка без командной строки
На странице репозитория нажмите **Add file → Upload files**, перетащите все файлы и папки и нажмите **Commit changes**.

```bash
git commit -m "Прототип: модуль «Юридический блок»"
```

## Структура

```

├── index.html        — каркас страницы
├── css/style.css     — стили в фирменных цветах «Эввива»
```

Чтобы поменять вопросы, критерии, пороги или ступени, правьте `js/data.js`.

## Что умеет прототип

Роли переключаются кнопками вверху страницы («Смотреть как»):

| Роль | Что делает |
|---|---|
| **Сотрудник** | Изучает 8 тем модуля, проходит тест (15 вопросов и кейс), видит этапы, итоговый балл, ступень и план развития |
| **Оценщик** (руководитель юридического департамента) | Ставит баллы 1–5, Н/О или Н/П по каждому критерию, пишет доказательства, заполняет лист заключений № 4, передаёт результаты в комиссию |
| **Комиссия / HR** | Видит сводку и вывод системы, выбирает решение и ступень, составляет план развития, отмечает утверждение генеральным директором |
| **Настройки** | Пороги вывода, матрица требований (профильная и непрофильная должность, обязательные критерии), ступени роста, банк вопросов |

### Правила расчёта (по методике оценки)
- Шкала 1–5. «Н/О» (не оценено) и «Н/П» (не применимо) не заменяются нулём и исключаются из делителя.
- Средний балл модуля равен сумме баллов, делённой на число оценённых критериев.
- Критерии с требованием «Нет» для данного типа должности автоматически получают «Н/П».
- Если балл по обязательному критерию ниже минимума, фиксируется дефицит, и вывод «Соответствует» не ставится.
- Система **предлагает** ступень по порогам, а окончательное решение принимает комиссия. Если комиссия выбирает другую ступень, нужно обоснование.
